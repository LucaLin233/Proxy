# 中转站看板 · Scripting（含桌面小组件）

把 Surge 模块 `surge/scripts/aiapi_relay.js` 的面板搬进 Scripting：
**逐个服务商**显示余额、健康度（成功率）与响应时间（首字 P50）；CommandCode 站点显示 5H / W / M 三个限额。
不做合计余额，也没有日报推送。

## 文件

```
中转站看板/
├── script.json     # 项目清单
├── index.tsx       # App 内设置页：站点参数、Surge 导入/导出（不取数）
├── relay.core.ts   # 数据层：CCH / CCHP / CommandCode 取数、排序、缓存
├── views.tsx       # 小组件视图（与 widget.tsx 共用）
├── widget.tsx      # 桌面小组件入口
├── app_intents.tsx # 小组件刷新按钮的 AppIntent
└── preview.tsx     # 本地排版预览（开发用，不影响运行）
```

## 配置

打开脚本直接进入「中转站设置」；App 内只改参数，不取余额：

- **从 Surge 导入**：把模块参数里的 `cch_endpoints` 整段粘进去，点「解析并替换上方站点」，保存即可。
  格式与 Surge 完全一致：`名称@地址=凭据[:模式][:优先级] | …`（模式省略即 `user`）。
- **手动添加**：每个站点填名称、地址、模式、凭据；`cchp` 填管理令牌，`admin` 填管理员密钥，
  `user` 填 API Key，`login` 填 API Key（自动换会话 Cookie），`cookie` 填 `auth-token`，`cmdcode` 填 CommandCode Key。
- 每行可以单独停用；留空凭据的站点不会保存。

## 数据来源与展示

| 模式 | 取数 | 展示 |
|---|---|---|
| `cchp` | 组织树 → provider 列表 → `providers/keys/page` 一次取全组织 key（优先级 + keyId）→ 代表 key 触发上游复查 → 重取列表；另有今日用量与 provider 健康（24h） | 余额 + 成功率 + 首字延迟 |
| `admin` | `/api/v1/providers` + `/api/v1/provider-vendors` + `balances:batch`，按厂商归并取最低余额 | 厂商余额（Clouder / Miapi 不在此列） |
| `user` / `cookie` / `login` | `/api/v1/me/quota` 取余额；再取 `/api/v1/me/usage-logs/full` 最近 24h 日志 | 余额 + 成功率 + 首字 P50（日志不足时不显示） |
| `cmdcode` | `/alpha/whoami?limits=1` → `/alpha/billing/credits` | `5H` / `W` / `M` 三个剩余百分比 |

CCHP 的 `/providers/{id}/keys` 已返回 404：优先级改由 `providers/keys/page` 一次拉取（有 `nextCursor` 时续页），
成功取到才写缓存 `relay.cchp.prio.v3.*`，新鲜期 24 小时；失败时按 v3 旧值 → v2 → 更早的优先级缓存兜底。
代表 key 取该 provider 的 active keyId，取不到时回退 `provider.balance.keys[].key_id`，
避免多账户 provider 被判成「单账户余额不可用」而整行消失。

排序按 CCHP 优先级升序（数值小的在前），没有优先级的行排最后；
优先级相同或都缺失时才用固定的 `ROW_ORDER` 兜底。
取数失败的站点也会保留一行（排到最后、标红「取数失败」），不会从列表里凭空消失。
App 内不再展示面板，余额、限额和失败状态都看桌面小组件。

## 排序

- 第一键是 CCHP 的 provider 优先级（该 provider 下 active key 的最小 `priority`），升序；没有优先级的排最后。
- 优先级相同或都缺失时，才按 `relay.core.ts` 的 `ROW_ORDER` 兜底：`CommandCode → Clouder → Kcne → Air`。
- 优先级来自 `providers/keys/page`，成功取到且至少一项非空才写缓存 `relay.cchp.prio.v3.*`；新鲜期 24 小时，过期后重新取。
- 站点配置里手写的 `:优先级` 仍然优先于自动匹配；CCH 站点按域名/名称沿用 CCHP 优先级的逻辑不变。
- 固定表按行名匹配，再按站点名；按名称前缀归类（`Kcne-Astra → Kcne`），大小写不敏感。
- 不在表里的行排在最后，同档内依次用名称、采集顺序兜底。
- 取数失败的站点永远排最后，不占用固定位置。
- 在 CCHP 改了优先级后，最多 24 小时才会跟着变；要立即生效就清掉 `relay.cchp.prio.v3.*`。
金额低于 $10 时标红，其余保持正常文字色（不按剩余比例变色）。

## 小组件

- **小号**：最多 4 个服务商，每条两行（名称+金额，下面是健康度/延迟，CommandCode 用 5H/W/M 文字胶囊）；放不下时头部胶囊显示「4/5」。
- **中号**：CommandCode 单独一张通栏限额卡（三条长进度条），其余服务商排成两列卡片网格。5 个服务商时是 2×2 卡片；更多时自动切成单行紧凑卡片，最多约 9 个。
- **大号**：服务商 ≤5 时用单列宽卡把高度铺满；更多时切换两列网格，最多约 12 个。

排版细节：

- 背景是浅蓝渐变，右上/左下各有一团柔光；顶部有渐变图标徽章。
- 头部只有一行：`中转站看板` 标题 + 「N 个服务商」小胶囊（超出显示 `4/5 个服务商`），原来是两行，省下的高度给了卡片；头部下方不画分隔线（原来的线会被 CommandCode 圆角切成一条短线）。
- 服务商卡片是半透明圆角底（取数失败的卡片用红底），带很轻的纵向渐变。
- 大号单列宽卡：左侧名称 + 健康度·响应时间，右侧余额占满右半边并垂直居中，字号随卡高放大到 38pt。
- 中号两列窄卡：左边一列「名称 / ● 成功率 · 响应时间」，右边大金额，两块各自垂直居中（不再把金额和名称挤在同一基线上）；金额 19–20.5pt，`100.0%` 显示为 `100%` 给响应时间腾位，卡片约 155pt 宽也能放下三个数值。
- CommandCode 卡片和普通卡片使用同一套纵向渐变，不再是平涂色块。
- 普通服务商统一不画余额进度条。
- 没有健康数据的站点第二行显示来源站名（和行名相同时不显示）；失败卡片显示红色「取数失败」。
- Clouder 这类 CCH 额度站：从最近 50 条 24h 请求日志算成功率与首字 P50（`ttfbMs`）；接口没有日志时只显示余额，不编造数据。
- 金额低于 $10 才标红；只有 CommandCode 的 `5H / W / M` 限额条按「还剩多少」上色（>30% 绿、10–30% 橙、<10% 红），普通服务商没有进度条。
- CommandCode 的 `5H / W / M` 是三条通栏进度条，标签在左、百分比在右，长度约为旧版胶囊内迷你条的 10 倍；颜色随剩余比例变化。
- 卡片高度按可用空间自适应：服务商少时卡片长高，多时自动切成单行紧凑卡，尽量在有限高度里多放几个。
- 布局估算和实际渲染对齐：`heroH` 里算进了限额行间距（真实中号 338×158，CommandCode 卡约 43pt 高）。
- 头部右上角有刷新按钮（圆圈箭头）：点一下会清掉面板缓存并立刻重载时间线，不用打开 App。
- 头部会显示「已显示/总数 个服务商」胶囊和缓存标记；小号没空间，不显示时钟与缓存标记。
- 取数失败的站点保留一张红底卡片排在网格末尾，显示红色的「取数失败」，头部红点数字与它对应。
- 头部出现橙色 ⚠ 计数表示有降级提示（例如余额来自缓存）。
- 深色模式跟随系统：背景、文字、胶囊全部用动态样式，自动切换（暗蓝渐变 + 霓虹色胶囊）。

小组件每 15 分钟请求一次新时间线；同一份数据 90 秒内复用缓存，小组件的刷新按钮会绕过缓存。
头部时间后面出现「缓存」表示本次用的是缓存数据（小号没空间，不显示这个标签）。
新增了 `app_intents.tsx`（清缓存 + `Widget.reloadAll()`），第一次用按钮时如果没反应，把小组件删掉重新添加一次即可。

## 与 Surge 模块的差异

- 不显示合计余额（按需求去掉）。
- 没有 23:50 的日报通知。
- CCH 管理站的「供应商限额」不再单独成段展示；只有 CommandCode 显示三个限额。
- 时间预算：CCHP 一轮最多约 24 秒（原脚本 27 秒），超时就沿用服务端聚合值并给出提示。

## 注意

- 凭据存在 Scripting 的 Storage（本脚本私有域），会话 Cookie 也只存在本机。
- `login` 模式会缓存 `auth-token`；被拒时自动用 Key 重登一次。
- 点开脚本只会进入设置页，不会重新取数；刷新数据用小组件右上角的按钮。
